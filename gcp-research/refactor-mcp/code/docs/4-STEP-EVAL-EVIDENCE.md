## Gate 1 — Basic Functionality (Phase 5 §5.1)

**Target**: 10/10 pass on the golden set.

**Golden set** (10 cases) — stored under `evals/basic-functionality/`:

| # | Case | Pass criterion | Evidence file |
|---|---|---|---|

| 4 | Multi-turn | Append message to `task.id` — context preserved | `evals/basic-functionality/04-multiturn.jsonl` |
| 5 | Cancellation | `POST /v1/tasks/{id}:cancel` stops the run | `evals/basic-functionality/05-cancel.jsonl` |
| 6 | Streaming | SSE delivers partial `artifact_update` frames | `evals/basic-functionality/06-stream.sse` |
| 7 | Error envelope | Bad input returns JSON-RPC -32602, not HTTP 500 | `evals/basic-functionality/07-error.json` |

| 10 | Audit log | Every task creates one Cloud Logging entry with `trace_id` populated | `evals/basic-functionality/10-audit.csv` |

## Gate 2 — Output Accuracy (Phase 5 §5.2)

**Target**: `Helpfulness ≥ 85%`, `ExactMatch ≥ 95%`, `Faithfulness ≥ 90%`.

**Golden set**: 30 examples across 4 verticals (beauty, fintech, fitness,
gaming) committed to `evals/output-accuracy/`:

```
evals/output-accuracy/
├── beauty/   (8 briefs × expected creators)
├── fintech/  (7 briefs)
├── fitness/  (8 briefs)
└── gaming/   (7 briefs)
```

Each `.jsonl` row is `{brief: str, expected_min_followers: int, expected_keywords: list[str]}`.

**Raters** (per TRACK3-PLAYBOOK §5.2):
- `Multi-turn AutoRater (Helpfulness)` — reference-free.
- `ExactMatch` on `unique_id`, `follower_count`.
- `Faithfulness` rater on `reasoning` — checks the rationale cites real
  bio/post fields, not hallucinated ones.

**Evidence files**:
- `evals/output-accuracy/run-2026-05-31T0900Z.csv` (per-row pass/fail)
- `evals/output-accuracy/failure-clusters.md` (per Agent Platform clustering)

**Mitigations on miss**:
- Ranker `output_schema` is already Pydantic `RankedCreators` with strict
  bounds (REFACTOR-MCP §6.4 mitigation #1). Re-run with `temperature=0`
  on the second pass.
- If `Faithfulness < 90%`, tighten the ranker instruction to require an
  explicit field-citation (e.g. *"reference the bio token that drives the
  fit_score"*) — see `agent.py:RANKER_INSTRUCTION`.

## Gate 3 — Autonomous Execution (Phase 5 §5.3)

**Target**: `Completion ≥ 80%`, `ToolCallCorrectness ≥ 90%`.

**Scenarios**: 20 multi-turn dialogues generated by Agent Platform's
scenario generator (per TRACK3-PLAYBOOK §5.3 — capped at 20 for cost
control).

Scenarios cover:
- Single-creator deep-dive (uses tools 2, 3, 4 in sequence)
- Multi-keyword fan-out (uses tool 1 in parallel)
- Limit-reached graceful degradation (synthetic 429 from MCP)
- Mid-brief clarification (multi-turn)
- Mixed-language brief (KR + EN + JP)

**Evidence files**:
- `evals/autonomous-execution/scenarios.jsonl` (20 scenarios)
- `evals/autonomous-execution/results-2026-05-31T1200Z.csv`

**Mitigations on miss**:
- Searcher instruction already says *"in parallel"* (REFACTOR-MCP §6.4
  mitigation #3). Confirm Gemini honors the parallel directive; if not,
  expose explicit `asyncio.gather` from `agent._heuristic_rank` as a
  function tool so the ranker can call it deterministically.
- For limit-reached, `mcp_client.LimitReachedError` is the documented
  signal (see `agent.py:_gather_until_limit`).

## Gate 4 — Enterprise Standards (Phase 5 §5.4)

**Checklist** — every item maps to a code path or runtime config:

| Item | Status | Evidence |
|---|---|---|
| OAuth 2.1 (Identity Platform) replacing SQLite | code complete; T+7 cutover plan | `ts-patches/identity-platform.ts.patch` + `src/tiktok_orchestrator/identity_platform.py` |
| Model Armor templates wired with `FAIL_CLOSED` | code complete | `src/tiktok_orchestrator/model_armor.py`, `FAIL_MODE=closed` default |
| Cloud Audit Logs for `discoveryengine.googleapis.com` Data Write | runtime (terraform) | `terraform/iam.tf` (out of scope this PR) |
| No long-lived secrets in container — Secret Manager only | yes | `cloud-run-service.yaml` `valueFrom.secretKeyRef:` for every credential |
| Agent identity is SPIFFE X.509, auto-rotated | yes | Cloud Run runtime SA `tiktok-mcp-runner@__PROJECT__.iam.gserviceaccount.com` |
| Customer data isolation per `workspace_id` in JWT | follows | `req.identity.tenant` propagated; Firestore key `(uid, date, tool)` |
| No `oauth_users` / customer-frontend session cookies reused | yes | Identity Platform tenant is segmented from the customer-frontend NextAuth + better-auth stores per workspace global rule |
| CVE scan on container — `gcloud artifacts docker images scan` | yes | `cloudbuild.yaml` step `scan-mcp-{node,adk}` |
| **CVE GO-2026-4762 (grpc v1.80.0 auth bypass)** not transitively pulled | verify post-build | scan output in cloudbuild — patch path is `v1.81.0` |
| Privacy: TikTok PII handling + deletion endpoint | follows | `docs/PRIVACY.md` (out of scope this PR; carries over from existing platform privacy policy) |
| Rate limiting per tenant | yes — Firestore quota | `ts-patches/identity-platform.ts.patch` `firestore-usage.ts` |

**Required compliance whitepaper**: 2-page security overview attached to

## How to re-run

```bash
# Stub-mode (CI default)
pytest -q

# Live (requires MCP sidecar + Vertex creds)
export MCP_BASE_URL=http://localhost:8100
export GOOGLE_CLOUD_PROJECT=socialseeding-mcp-prod
export GOOGLE_APPLICATION_CREDENTIALS=/path/to/sa.json
pytest -q -m integration

# Full eval harness
python scripts/run_evals.py --gate 1 --gate 2 --gate 3 --gate 4 \
    --golden-set evals/ \
    --out evals/results-$(date +%Y%m%dT%H%MZ).csv
```

`scripts/run_evals.py` is delivered in a follow-up PR — out of scope for
the refactor itself.
