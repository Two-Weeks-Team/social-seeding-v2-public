2. MongoDB 셋업 — 신규 Atlas 계정 기준 (상세)

v2의 데이터 모델: Mission Control(apps/web)의 ~20개 페이지와 워크플로가 @ss/db로 MongoDB를 직접 read/write 합니다(packages/db/src/client.ts → MONGODB_URI, DB명 기본 social_seeding). v2는 v2_* 컬렉션만 소유하고, v1 공유 컬렉션(accounts_tiktok·workspaces·user_tokens·crm_accounts·templates·unified_emails…)은 read + additive-only입니다.

2-A. 옵션 비교 — 어떤 Mongo를 쓸까

옵션용도설정주의
인메모리 mongodb-memory-server로컬 dev/test (권장 기본)pnpm run dev-mongo → :27027. MONGODB_URI=mongodb://127.0.0.1:27027휘발성(프로세스 종료 시 소멸). 무권한.
본인 Atlas dev 클러스터지속 로컬 dev, 배포 재현§2-B무료 M0 가능. 본인 계정.
공유 Atlas (v1과 동일)실데이터 연동·프로덕션운영자에게 URI 수령 → 시크릿prod 데이터. write는 v2_*·additive만. run-demo.ts는 공유 prod 직접쓰기 거부.

2-B. 신규 Atlas 클러스터 만들기 (제로부터)

계정 + 클러스터: cloud.mongodb.com 가입 → 새 Project → "Build a Database" → M0(Free) 또는 dedicated → 리전 선택(Cloud Run과 가까운 곳).
DB 사용자: Database Access → Add user (SCRAM, 강한 비번) → role readWrite@social_seeding (또는 Atlas admin for dev).
네트워크 접근: Network Access → 로컬 dev는 본인 IP 추가. Cloud Run에서 붙이려면 SRV 연결이라 0.0.0.0/0 허용(또는 VPC peering/Private Endpoint — 운영 권장). 0.0.0.0/0는 인증으로만 보호되므로 강한 DB 비번 필수.
연결 문자열: "Connect" → "Drivers" → mongodb+srv://<user>:<pass>@<cluster>/?retryWrites=true&w=majority. DB명은 코드가 MONGODB_DB(기본 social_seeding)로 붙이므로 경로에 DB명 불필요.
인덱스 생성: MONGODB_URI를 .env.local(또는 ambient env)에 넣고 
pnpm exec tsx scripts/init-indexes.ts
→ 아래 22개 인덱스가 idempotent하게 생성됩니다.

2-D. 클라우드(Cloud Run)에 Mongo 연결 = 시크릿

# URI를 Secret Manager에 저장 (값은 셸 히스토리/채팅에 남기지 말 것)
printf '%s' '<MONGODB_URI>' | gcloud secrets create mongodb-uri \
  --project <PROJECT> --replication-policy=automatic --data-file=-
# 런타임 SA에 accessor 부여
gcloud secrets add-iam-policy-binding mongodb-uri --project <PROJECT> \
  --member="serviceAccount:<RUNTIME_SA>" --role="roles/secretmanager.secretAccessor"
# 서비스에 배선 (기존 env/시크릿 보존)
gcloud run services update ss-v2-web --project <PROJECT> --region <REGION> \
  --update-secrets=MONGODB_URI=mongodb-uri:latest
# MONGODB_DB는 코드 기본값 social_seeding이라 별도 불필요
왜 백엔드 API가 아니라 직접 Mongo? v1 백엔드 API는 v1 도메인(CRM·토큰·TikTok 프록시)만 노출합니다. 캠페인/승인/리드 같은 v2_* 상태는 v2가 새로 만든 컬렉션이라 백엔드에 엔드포인트가 없습니다. 그래서 v2 web은 v1과 같은 Atlas 클러스터에 직접 연결합니다(CLAUDE.md: "DB = v1과 같은 Atlas"). 단, v2_*만 쓰고 공유 컬렉션은 read/additive.

3. Google OAuth 셋업 — 로그인 + Gmail

두 가지 흐름이 하나의 OAuth 클라이언트 + 하나의 콜백(/api/auth/google/callback)을 공유합니다. 콜백이 state.purpose로 분기:

흐름startscope콜백 동작앱검증
로그인/api/auth/google/startopenid email profileid_token→sub/email→signSession→ss_session 쿠키불필요
Gmail 연결/api/auth/gmail/startgmail.send gmail.readonlyrefresh token→공유 백엔드 user_tokens 저장필요(민감)

3-A. 공유 클라이언트 재사용 (가장 빠름)

운영자 클라이언트(842411…, 프로젝트 balmy-apogee-452007-r5)의 client_id/secret을 받아 env/시크릿에 넣고, 콜백 URI에 본인 origin을 추가 등록받으면 끝. localhost와 agents.socialseed.ing는 이미 등록됨.

3-B. 본인 신규 OAuth 클라이언트 (독립 재현)

OAuth 동의화면: GCP Console → APIs & Services → OAuth consent screen → User type External → 앱 이름/지원 이메일. Scopes에 openid·email·profile(로그인) + (Gmail 쓸 거면) gmail.send·gmail.readonly.
Test users 추가: Publishing status가 "Testing"이면 등록된 test user만 로그인/연결 가능(+ refresh token 7일 만료). 공개 사용자 대상이면 "Production" 전환 + gmail.send 민감 스코프 Google 검증(수 주) 필요. 로그인용 openid/email은 검증 불필요.
OAuth 클라이언트(Web) 생성 → Authorized redirect URIs:
http://localhost:3000/api/auth/google/callback
https://<your-domain-or-cloud-run-url>/api/auth/google/callback
client_id/client_secret → 로컬은 .env.local(GOOGLE_CLIENT_ID/SECRET), 클라우드는 Secret Manager(google-oauth-client-id/google-oauth-client-secret → 서비스가 GOOGLE_OAUTH_CLIENT_ID/SECRET로 주입). 코드는 두 이름 모두 허용(gmail-oauth.ts googleClientId()).
로그인 콜백은 origin을 GMAIL_OAUTH_ORIGIN(설정 시) 또는 요청 origin으로 잡습니다. 배포 시 GMAIL_OAUTH_ORIGIN=https://<도메인>을 등록된 redirect와 일치시키세요.

배포 (web)

# 1) 랜딩 — 200 + 리다이렉트 아님
curl -sS -o /dev/null -w "%{http_code}\n" https://<DOMAIN>/        # 200
# 2) 로그인 라우트 — 302 → Google consent (openid email profile)
curl -sS -o /dev/null -D - 'https://<DOMAIN>/api/auth/google/start?returnUrl=/campaigns' | grep -i location
#   → accounts.google.com/...&scope=openid+email+profile&redirect_uri=.../api/auth/google/callback
# 3) 리비전 + 시크릿 배선 확인
gcloud run services describe ss-v2-web --project <PROJECT> --region <REGION> \
  --format='value(status.latestReadyRevisionName)'
# 4) 로그인 후(브라우저): /campaigns 정상 렌더 + /settings에서 "Gmail 연결" → 동의 → 연결됨
재현 성공 기준: 게이트 green · 랜딩 200 · 로그인 302(scope=openid email profile) · 로그인 후 /campaigns 500 아님(= MONGODB_URI 배선됨) · /settings에서 Gmail 연결 시 연결됨 pill.
