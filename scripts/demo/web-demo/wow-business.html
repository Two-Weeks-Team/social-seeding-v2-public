Optimize We built it — then we hardened it · stall → repair

The middle act of one story (Build → Optimize → Refactor). When a creator reply is ambiguous — interested, but quietly negotiating a rate — the conversation_responder stalled at the auto-respond ↔ escalate boundary. We made it measurable and fixed it. D29-A D50 D27

Before · baseline triage STALL
Reply: "Love it! my rate is ~$800, ok?" → classifier rounds to interested.
  1. has_minimum_context = true → continue
  2. classification == negotiating = false → continue
  3. (no rate-signal rule) → fallthrough → respond
✗ respond · auto-drafts a reply with no rate-handling fact — oscillates at the boundary.
After · optimized triage (live) REPAIRED
Optimizer applies rate_signal_on_positive.
  1. has_minimum_context = true → continue
  2. classification in {declined, unsubscribe} = false → continue
  3. classification == negotiating = false → continue
  4. interested AND proposed_rate_usd ≠ None = true → escalate
✓ escalate → human · a proposed rate = negotiation; never mint a mandate here (D27).
